# Proposal

## Why

Hand pointing is imprecise: a hand pointer drifts a few pixels while pinching, so small buttons are missed and drawn lines land wherever the hand happened to be. Drawing needs the aids every CAD user expects (snap, ortho, projection), and the user needs to bring an existing Rhino model into the viewer. Today there is no way to do that at all: the app opens only its own `scene.hai.json` project file, and nothing in the code reads a `.3dm`. So "fix the import" means building 3DM import for the first time.

## What Changes

- **Buttons catch the hand.** When a hand pointer comes near an on-screen control, it snaps to the nearest one: the pointer locks onto it, the control is outlined, and a pinch presses it. The lock is sticky (it needs a larger distance to let go), holds for the whole pinch, and never grabs while a tool or the view is being dragged. A new feature switch, "Snap to buttons", turns it off.
- **Drawing aids in Settings.** A new "Drawing aids" page with one switch each: **Grid** (what the tools do today), **Ortho** (lines lock to the X or Y axis, or to 45 degrees), **Endpoint**, **Midpoint**, **Centre**, **Project** (the point is projected onto the nearest existing edge or surface point) and **Perpendicular** (the foot of the perpendicular from the line's start onto an existing edge). The create tools (Wall, Slab, Column, Copy) and Move use them. The snapped point shows a marker with its name, and the notice shows length and angle. The aids are kept in the workspace settings; only Grid is on until the user turns the others on.
- **3DM import.** An Import button in the project bar and dropping a `.3dm` file on the viewer read the file in the browser with rhino3dm (MIT, WebAssembly, in a Web Worker): meshes, Breps and extrusions become reference meshes, scaled to millimetres, with their layer names and colours. The geometry is saved in the project folder as an asset, so the scene file stays small. Curves, points, annotations and anything unreadable are counted and reported, never silently dropped. Imported geometry can be selected, measured, moved, copied, deleted, sectioned and snapped to, and the agent sees it as elements with a name, layer and bounds. Import is one undo step.
- Roadmap: this becomes Week 11; the Rhino connector and later weeks move down by one.

Out of scope: writing `.3dm` (export), editing imported geometry (no vertex or face editing; it is a reference), importing curves as drawable lines, materials and textures beyond one colour per object, IFC/OBJ/glTF import (the asset format keeps the door open), live link to the file on disk, Rhino itself (next change), and snapping to the mesh surface of imported geometry (only to its bounding box corners and centre).

Demo clip (Week 11, 30-60 s): "Drop in my Rhino model, then draw a wall that snaps exactly to its corner": drag a `.3dm` onto the viewer, see it appear with a report, point near the settings gear and watch the pointer lock on, switch on Endpoint and Ortho in the Drawing aids page, then draw a wall by hand that snaps to the model's corner and runs square.

## Capabilities

### New Capabilities

- `drawing-aids`: the snap, ortho, projection and related aids for drawing and moving, their settings page, and their on-screen feedback.
- `model-import`: reading a `.3dm` file into the project as reference geometry, with a report of what was and was not imported.

### Modified Capabilities

- `tool-palette`: adds the hand pointer snapping to nearby controls (an ADDED requirement beside "Hands can press on-screen controls"; the other in-flight changes touching this spec are `add-studio-ui` and `add-two-hand-input`, so only an added requirement is used here to avoid a clash).
- `scene-model`: adds the imported-geometry element type and its storage as a project asset.

## Impact

- `packages/protocol`: `imported` element type, `DrawingAids` in the settings, the `snapToButtons` feature, asset fields.
- `packages/scene`: bounds for imported elements; pure snap solver (`snap.ts`) so it is unit-testable without a browser.
- `apps/bridge`: asset upload and download endpoints behind the session token, asset files in the project folder, `import` scene operation, size limits.
- `apps/web`: `perception`-side pointer snapping in the viewer's pointer loop; the drawing-aids page and marker overlay; `import/` (worker, picker, drop zone, report); the imported mesh rendering in the viewer.
- New dependency: `rhino3dm` (MIT licence; its WASM file is served from our own origin, never a CDN). It must pass the licence check.
- Tests need a small `.3dm` fixture set generated by a script with rhino3dm (no Rhino install needed).
- Docs: `docs/settings.md`, `docs/tools.md`, new `docs/import.md`, and the roadmap in `docs/PLAN.md` and `README.md`.
